## Command sequences

Kopia (config/cache/log dirs isolated under the spike dir; password `spike-test`):

```
kopia repository create filesystem --path <repo> --password spike-test --no-check-for-updates
time kopia snapshot create <corpus>
kopia snapshot list
time kopia snapshot restore <snapshot-id> <dest>
time kopia snapshot verify          # no ids => all snapshots
kopia ls <root-dir-id>              # read-only browse (FUSE unavailable, see below)
```

Restic:

```
RESTIC_REPOSITORY=<repo> RESTIC_PASSWORD=spike-test restic init
time restic backup <corpus>
restic snapshots
time restic restore latest --target <dest>
time restic check
restic ls latest                    # read-only browse; no FUSE in restic
```

Plakar (repo/passphrase via `PLAKAR_REPOSITORY` / `PLAKAR_PASSPHRASE`; config/cache/data dirs isolated):

```
plakar create
time plakar backup <corpus>
plakar ls
time plakar restore -to <dest>      # latest snapshot
time plakar check
plakar ls <snapshot-id>             # read-only browse
```

Note: plakar's first `create` invocation appeared to hang because output was piped into `head` (SIGPIPE killed it mid-run); re-run without a closing pipe succeeded. Second backup was deleted (`plakar rm -apply`) so the final repo contains exactly one snapshot like the other two engines.

## Results

All times are wall-clock from `/usr/bin/time -p` (first backup only; plakar second-run note below). Repo sizes via `du -sk`. Ratio = repo KiB / corpus KiB (148,116).

| Engine | Corpus bytes | Repo bytes (KiB) | Ratio (repo/corpus) | Backup (s) | Restore (s) | Verify result | Verify (s) | Restore content |
| --- | ---: | ---: | ---: | ---: | ---: | --- | ---: | --- |
| Kopia v0.23.1 | 151,546,003 | 98,976 | 0.668 | 0.42 | 1.02 | `snapshot verify`: no errors | 0.30 | identical (`diff -r` OK) |
| Restic 0.19.1 | 151,546,003 | 57,764 | 0.390 | 1.28 | 1.09 | `restic check`: no errors were found | 0.84 | identical (`diff -r` OK) |
| Plakar v1.1.4 | 151,546,003 | 64,548 | 0.436 | 54.54 (first), 1.65 (second run) | 1.72 | `plakar check`: completed without errors | 1.81 | identical (`diff -r` OK) |

Notes:

- Kopia reports stored content of 101,268,734 B across 148 contents; snapshot logical size 151.5 MB. Backup was timed on a fresh repository (same corpus, same flags); repo/restore/verify measured on the first repo (98,976 KiB vs 98,984 KiB on the fresh one — noise).
- Restic backed up 139 files / 144.526 MiB, one snapshot `5179f807`.
- Plakar backup #1 (54.54 s) includes cold-start cost (state/plugin setup); the engine itself reported "backup completed without errors in 515 ms". Incremental second backup: 1.65 s. Backup wrote 62 MiB to the repo.
- Effective dedup+compression reduction vs corpus: Kopia ≈33%, Plakar ≈56%, Restic ≈61% (Restic smallest, then Plakar, then Kopia).

## Preliminary observations (not conclusions)

- On this corpus all three engines verified cleanly and restored byte-identical content.
- Restic produced the smallest repo and was the only engine whose default first-backup completed quickly (1.28 s); Plakar's cold-start cost (≈54 s) dominates its first run but its steady-state incremental run (1.65 s) is comparable to the others.
- Kopia's repo was ~1.7× larger than Restic's on this corpus (97 MB vs 56 MB). This is one corpus on one machine; it must not be read as a general ranking.
- Plakar and Restic compress/dedup the zeros/text-heavy sections well; the 60 MB of seeded-random data is incompressible for all three.
- First run only: no Linux, no NAS/NFS storage backend, no S3, no encryption-on/off comparison, no multi-snapshot retention, no long-term operations.

## Limitations

- Single host, single OS (macOS 26.5.2, APFS); the project's reference deployment is Linux, which must be re-run.
- Times include filesystem page-cache effects (all repos on the same local disk); no cold-cache or remote-storage runs.
- Kopia and Restic defaults used; no tuning (kopia splitter/compression level, restic pack size, plakar packfile/compression options) was performed.
- Encryption was left at engine defaults: Kopia/Restic encrypt by default; Plakar encrypts by default (would have required `-plaintext` to disable) — no encryption overhead comparison made.
- Restored-content comparison is `diff -r` on a local APFS volume; xattrs/permissions beyond mode/owner were not compared.
- FUSE/mount comparison impossible on this host (macFUSE absent).

## Re-running on Linux/NAS

- Re-run with `scripts/qualification-spike.sh --corpus-dir <dir> --work-dir <dir> [--size-mb N]` (pure bash + awk + dd; no bubblewrap/container sandbox needed — it is a plain user-space corpus + repo run). Engine paths are overridable via `KOPIA_BIN`/`RESTIC_BIN`/`PLAKAR_BIN` (default `PATH`); results land in `<work-dir>/results.tsv` and `results.md`.
- Run as a regular user: Kopia and Plakar need no privileges; `restic restore` may need `root` or `--allow-root` if the snapshot contains root-owned files (and `restic check` is fully offline). The openat2/`O_BENEATH`-style hardening topics are Linux implementation details and are not exercised by this script.
- Plakar's first-backup cold-start cost (~50 s+ on this host) is expected; FUSE is only needed for `plakar mount` (requires libfuse on Linux) and is not part of this qualification. Note for Plakar v1.1.x: `plakar -disable-security-check create` exits 0 but creates nothing — the script uses plain `plakar create`.
